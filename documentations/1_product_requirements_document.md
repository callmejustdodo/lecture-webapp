**표기**

## 1. 제품 개요

AI·Claude 활용 강의를 결제부터 라이브, 다시 보기까지 한곳에서 하는 강의 플랫폼이다.

- 강사는 가입해서 강의를 열고, 자료를 쓰고, 라이브를 진행하고, 녹화본을 올린다.
- 수강생은 결제하고 로그인해서 라이브를 듣고, 자료와 녹화본을 보며 질문하고 진도를 관리한다.
- 운영자는 강사와 강의를 승인하고 정산과 분쟁을 처리한다.

### 전제

| 항목 | 내용 |
|---|---|
| 첫 사용 | 2027년 1월 중 개강하는 운영자 본인의 강의 ❓ 정확한 날짜 |
| 규모 | 한 기수 100명 이상 |
| 판매 단위 | 강의(기수) 단위 1회 결제. 구독 없음 |
| 결제 | 국내 카드·간편결제만. 해외 결제 없음 |
| 언어 | 한국어만 |
| 기기 | 데스크톱 브라우저 우선. 모바일 브라우저에서도 수강(열람·재생·질문)이 가능해야 한다. 네이티브 앱 없음 (가정) |

## 2. 역할과 권한

한 계정이 여러 역할을 가질 수 있다. 강사도 다른 강사의 강의를 수강생으로 살 수 있다.

| 역할 | 얻는 방법 | 할 수 있는 일 |
|---|---|---|
| 방문자 | 로그인하지 않음 | 강의 목록과 소개 페이지 보기 |
| 수강생 | 가입 후 강의 결제 | 등록한 강의의 자료·녹화본·라이브·질문 게시판 이용, 환불 신청 |
| 강사 | 누구나 강사 신청, 운영자 승인 후 | 자기 강의 만들기·수정, 라이브, 질문 답변, 자기 강의의 수강생·매출 보기 |
| 운영자 | 직접 지정 | 모든 강의와 사용자 관리, 강사·강의 승인, 정산, 환불 수동 처리 |

**접근 규칙**

- 강의 콘텐츠(자료, 녹화본, 라이브, 질문 게시판)는 그 강의에 **유효한 등록**이 있는 수강생, 그 강의의 강사, 운영자만 볼 수 있다.
- 유효한 등록이란 결제가 끝났고, 환불되지 않았고, 수강 기간이 끝나지 않은 등록이다.
- 강사는 다른 강사의 강의 관리 화면과 수강생 정보를 볼 수 없다.
- 권한 검사는 서버에서 한다. 화면에서 숨기는 것만으로는 충족되지 않는다.

## 3. 핵심 흐름

**수강생**

1. 소개 페이지에서 강의를 보고 결제 버튼을 누른다.
2. 가입 또는 로그인한다. 휴대폰 번호를 입력하고 약관과 알림 수신에 동의한다.
3. 결제한다. 끝나면 바로 강의에 들어갈 수 있고 알림톡으로 결제 완료 안내를 받는다.
4. 라이브 시작 전에 알림톡을 받고, 앱에서 라이브에 입장한다.
5. 라이브가 끝나면 녹화본과 자료를 보며 레슨을 완료 처리한다.
6. 막히면 레슨에서 질문을 남기고, 답변이 달리면 알림톡을 받는다.
7. 수강 기간이 끝나기 전에 만료 안내를 받는다. 끝나면 콘텐츠 접근이 닫힌다.

**강사**

1. 강사로 신청하고 승인을 받는다.
2. 강의를 만든다: 소개, 가격, 일정, 챕터와 레슨.
3. 강의를 공개 신청하고, 승인되면 판매가 시작된다.
4. 예정된 시간에 앱에서 라이브를 연다. 끝나면 녹화본이 해당 레슨에 붙는다.
5. 질문에 답하고, 현황판에서 수강생 진도와 매출을 본다.
6. 정산 주기마다 정산 내역을 확인하고 지급받는다.

## 4. 기능 요구사항

우선순위: **P0** 개강에 반드시 필요 · **P1** 개강 전 범위이지만 없어도 강의는 진행 가능

### 4.1 계정과 로그인 (AUTH)

| ID | 요구사항 | 우선 |
|---|---|---|
| AUTH-1 | 카카오 로그인과 구글 로그인으로 가입·로그인한다. 이메일·비밀번호 가입은 없다. | P0 |
| AUTH-2 | 가입할 때 이름, 이메일, 휴대폰 번호를 받는다. 휴대폰 번호는 본인 확인(인증번호)을 거친다. (가정) | P0 |
| AUTH-3 | 이용약관, 개인정보 수집·이용, 알림톡 수신에 대한 동의를 받고 동의 시각을 기록한다. | P0 |
| AUTH-4 | 내 정보(이름, 휴대폰 번호, 알림 수신 설정)를 수정할 수 있다. | P0 |
| AUTH-5 | 회원 탈퇴를 할 수 있다. 법으로 보관해야 하는 결제 기록은 남긴다. | P1 |
| AUTH-6 | 로그인은 여러 기기에서 할 수 있지만 녹화본과 라이브는 한 번에 한 기기에서만 재생된다. 다른 기기에서 재생을 시작하면 먼저 보던 기기의 재생이 멈춘다. | P0 |

### 4.4 환불 (RFD)

| ID | 요구사항 | 우선 |
|---|---|---|
| RFD-1 | 수강생은 앱에서 환불을 신청할 수 있다. 신청 전에 환불 예정 금액을 보여 준다. | P0 |
| RFD-2 | 환불 금액은 강의의 환불 규정에 따라 자동으로 계산한다. 강사가 강의마다 아래 세 가지 중 하나를 고른다. 모든 방식에서 개강 전에는 전액 환불한다. | P0 |
| RFD-3 | 규정상 환불 대상이면 PG를 통해 자동으로 환불(전액 또는 부분)하고, 등록을 끝내 접근을 회수한다. | P0 |
| RFD-4 | PG 환불이 실패하면 등록 상태를 바꾸지 않고 운영자에게 알린다. | P0 |
| RFD-5 | 운영자는 규정과 다른 금액으로 수동 환불할 수 있다. 사유를 기록한다. | P0 |
| RFD-6 | 환불 금액은 해당 강사의 정산에서 차감된다. | P0 |
| RFD-7 | 등록 시점의 환불 규정을 등록에 함께 저장한다. 환불 계산은 저장된 규정으로 한다. | P0 |

**환불 규정 방식**

| 방식 | 개강 후 환불 금액 | 강사가 정하는 값 |
|---|---|---|
| 비율 차감 | 진행된 수업 횟수 비율만큼 빼고 환불 | 없음 |
| 구간제 | 전체의 1/3 진행 전 2/3 환불, 1/2 진행 전 1/2 환불, 그 후 환불 없음 | 없음 |
| 기간 내 전액 | 개강 후 N일 안에는 전액, 그 후 환불 없음 | N (기본 7일) |

"진행"은 예정된 라이브 수업 중 시작 시각이 지난 횟수로 센다. (가정)

## 10. 만드는 순서와 선행 작업

개발은 코딩 에이전트에게 맡기므로 개발 기간은 제약으로 보지 않는다. 4절의 기능을 모두 개강 전 범위에 둔다.

### 만드는 순서

뒤 단계가 앞 단계에 의존한다.

1. 데이터 구조, AUTH, 역할과 권한
2. STUDIO(강의·레슨 편집), LEARN, CAT
3. PAY, TERM, RFD
4. VOD, PROG
5. QNA, NOTI
6. LIVE
7. 강사 신청·승인, SETL, ADMIN
8. 실제 자료 입력, 결제·환불·라이브 리허설

### 코드로 줄일 수 없는 대기 시간

외부 심사와 계약에 걸리는 시간이다. 개강일은 여기에 좌우되므로 바로 시작한다.

- **PG 가입·심사**: 심사에 서비스 화면(상품, 약관, 환불 규정)이 필요한 경우가 많다. 다른 강사 강의 판매에 맞는 계약 형태인지 신청 전에 확인한다.
- **알림톡**: 발신 프로필 등록, 템플릿별 사전 심사 (카카오톡 채널은 이미 있음)
- **카카오 로그인**: 휴대폰 번호 제공 동의를 받기 위한 비즈 앱 전환과 검수
- **영상·라이브 서비스 계약**: 서비스 선정, 비용 확인, 계정 발급
- **법적 요건 확인**: 다른 강사의 강의를 대신 판매하면 통신판매중개에 해당할 수 있어 약관, 정산, 세금 처리를 확인한다.
- **약관·개인정보처리방침·환불 규정 작성**: 휴대폰 번호 수집과 알림 수신 동의 문구를 포함한다.
- **리허설**: 100명 이상 동시 접속과 실결제·환불은 사람이 직접 확인한다.
